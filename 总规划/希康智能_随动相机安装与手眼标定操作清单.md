# 希康智能随动相机安装与手眼标定操作清单

日期：2026年10月10日。适用：D435i安装在机械臂上，UI、控制、相机与识别共3个业务进程。此文件说明准备和操作方法，不包含已经求得的标定参数；不修改设备，不运行机械臂。

## 1 照片中的安装位置是否合适

如果所指位置是照片中“腕部附近、工具上方的侧面”，可以作为D435i的安装候选。与安装在工具最下端相比，这个位置可能更容易保留工具操作空间、减少镜头与皮肤过近、布置支架和线缆，但是否更好仍需在实际机器人上检查观察位视野、遮挡和整段运动路径。

照片不足以确认银色开孔模块的实际传感器类型，也看不清它究竟连接哪一个活动部件，不能按外观认定它就是相机或末端法兰。开孔面的朝向也不应直接照搬到D435i；需要让实际彩色镜头和双目深度模块在观察位都看向目标区域。

最重要的安装条件是：相机相对用于计算的参考部件保持刚性固定。

| 实际固定位置 | 应采用的参考位姿 | 能否直接用法兰手眼标定 |
|---|---|---|
| 第六轴输出法兰或与其刚性相连的工具安装板 | 实际法兰相对基座位姿 | 可以 |
| 第六轴之前的腕部外壳/前臂连杆 | 该实际连杆相对基座位姿 | 不可以套用固定法兰外参，需要该连杆位姿 |
| 存在松动、可自由转动的夹具 | 没有稳定参考关系 | 先解决机械固定，再标定 |

优先选择能从SDK或经过验证的运动学中稳定获得位姿的安装参考。相机靠近法兰并不等于固定在法兰上。机械结构确认应依据装配图和现场关节关系，不能只看照片。

安装要求：支架刚性锁紧；不挡彩色和深度镜头；避免热源、烟雾和工具遮挡；将相机、支架和线缆纳入负载与碰撞检查；USB线有应力释放和关节活动余量。最终固定后再标定，不能标定完又调整相机朝向。

## 2 需要准备的东西

| 类别 | 准备内容 | 本项目处理 |
|---|---|---|
| 相机 | D435i及稳定的USB连接 | 使用现有设备；只允许一个程序占用相机 |
| 安装件 | 刚性支架、配套紧固件、线缆固定件 | 按实际法兰/连杆设计，不依靠松动夹具 |
| 标定板 | 尺寸已知、平整、不反光的棋盘格板；或定义明确的ChArUco板 | 初版选其中一种，不混用参数 |
| 固定工具 | 刚性底板、夹具/固定座 | 标定板固定在床旁工装或固定工作台上，不放软床垫、不手持 |
| 尺寸测量 | 卡尺或可靠尺具 | 复核实际格子边长；纸板打印不能自动缩放 |
| 机器人操作 | 可用示教器、低速调试条件和实际位姿读取 | 标定时在无人接触的工装区执行，工具不输出能量 |
| 软件 | RealSense采集、棋盘角点/PnP、位姿记录、手眼求解和验证程序 | 现有zhenjiu覆盖相机采集，但还没有完整标定采集/求解流程 |
| 验证工装 | 不参与求解的固定目标点及其独立测量方法 | 检查多姿态一致性与绝对坐标误差 |

一种可试用的棋盘格规格：9×6个内角点，对应10×7个方格，方格边长30mm，图案尺寸300×210mm，可在A3纸上留白打印后平整贴在刚性板上。注意“内角点数量”和“方格数量”不是一回事。30mm是试制规格，不是所有观察距离的最优尺寸；试拍确认整板可见、角点清晰后再确定。

普通打印板适合跑通初版流程。打印比例、板面弯曲和测量误差都会影响结果，精度验收不能只依据打印文件上的尺寸。若改用ChArUco，保存方格尺寸、标记尺寸、字典和板面布局，标记编号属于标定图案自身定义，与UI业务报文是否使用ID无关。

## 3 标定究竟在求什么

先约定安装参考为法兰F，机器人基座为B，相机彩色光学坐标系为C，固定标定板为P。T_A_B表示把B坐标下的点变换到A坐标。手眼标定需要求出不随运动改变的T_F_C，即相机到法兰的固定变换。

每个采集姿态需要两项配对数据：机器人给出T_B_F，标定板图像结合相机内参算出T_C_P。板在基座下不动，所以多次采集应满足：

```text
T_B_P = T_B_F(i) × T_F_C × T_C_P(i)
```

不需要预先准确知道标定板相对基座的位置，但标定板在整批手眼采集中必须固定。世界坐标仍与机器人基座重合，不把标定板或相机当成随意变化的世界原点。

OpenCV的calibrateHandEye以gripper2base和target2cam为输入，输出cam2gripper；将gripper定义为法兰时，输出就是T_F_C。它要求包含不同方向的旋转运动，单纯重复平移不能充分约束结果。[OpenCV手眼标定接口与流程](https://docs.opencv.org/4.13.0/d9/d0c/group__calib3d.html)

## 4 按什么顺序操作

### 第一步 固定相机和标定板

先确定相机究竟固定在法兰还是其他连杆，锁紧支架，完成负载和线缆配置。板放在机器人能够从多个姿态看到的固定工装上，避免运动路径碰到板或支架。此时先不开穴位模型，也不需要真人。

### 第二步 确认彩色图像内参

沿用实际识别使用的彩色流配置，例如当前640×480。读取fx、fy、cx、cy以及畸变模型/系数，保存原始图像尺寸和流配置。D435i提供的出厂参数可用于起步验证；角点重投影表现或实测精度不满足要求时，再做相机内参标定或检查流配置。

本项目深度对齐到彩色，目标是标定彩色光学坐标系。PnP使用的图像、内参和畸变处理必须一致。不能拿深度相机内参代替彩色内参，也不能未经确认把不同畸变模型的系数直接交给OpenCV。

初版尽量保存未裁剪、未镜像、未旋转的原始彩色图。若做了缩放/裁剪/去畸变，必须同步更新投影模型；不能在原始和处理图之间混用内参。相机内部的彩色-深度标定与机械臂手眼标定是两件事。

### 第三步 确认机器人实际位姿含义

必须确定返回的是“哪个TCP/法兰、相对Base还是用户坐标、毫米还是米、姿态角是什么顺序”。读取实际反馈，不使用命令目标位置。SDK是否连上并不能证明坐标已经正确。

本地CPS.py的HRIF_ReadActTcpPos从HRIF_ReadActPos的第6至11项提取TCP实际位姿。因此不能把这个函数返回值直接当作法兰位姿。若得到的是基座下TCP位姿，且工具变换T_F_TCP已知，则：

```text
T_B_F = T_B_TCP × inverse(T_F_TCP)
```

如返回值相对于用户坐标系，还需先转换到Base。姿态角到旋转矩阵的变换按当前厂家手册和已知姿态核验，不能把Rx/Ry/Rz名字等同于任意软件的欧拉角顺序。也可使用法兰作为本次标定参考工具，但必须确认控制器定义与数据输出，不为省事随意覆盖生产工具配置。

如果相机固定在前臂连杆，应获取T_B_link并改求T_link_C；若无法可靠获取该连杆位姿，应先调整安装或完善运动学，不继续套用法兰数据。

### 第四步 停稳采集多组数据

建议初版采集20至30组有效姿态，再另外留5至10组不参与求解的验证姿态。这是工程采集建议，不是仅凭数量就能保证成功。

每组操作：低速移动到已检查的姿态 → 确认机械臂实际停稳 → 获取新鲜彩色图 → 记录同次采集前后的实际位姿 → 检查板角点 → 保存数据。板保持不动，机器人及相机变换位置和方向，包含绕至少两个不平行轴的旋转，并覆盖实际观察区。不能只左右平移或始终保持相机朝向不变。

采集时检查：整板可见、无明显反光和模糊；角点顺序/板原点一致；各姿态不是几乎重复；相机支架无位移。样本不合格就重采，不用低质量样本凑数量。可使用带可辨识方向的板避免角点原点翻转。

每组至少保存：原始彩色图、采集时间/机器人读数时间、实际位姿与参考系、当前TCP/UCS配置、内参、角点及检测结果。相机硬件时间与主机时间若来源不同，要记录其时间域，不能直接当作同一个时钟比较；停稳前后读数一致可辅助验证本次配对。

### 第五步 求解相机与法兰的固定关系

根据板的真实尺寸和角点，用PnP获得每张图的T_C_P，再将其与同组T_B_F送入手眼求解器。全部平移量用统一单位，建议内部使用m。保存T_F_C的旋转矩阵和平移，不只保存三个位置偏移。

同时计算每组的板重投影误差，以及转换后T_B_P的离散情况，检查错配、角点顺序、姿态方向和异常样本。剔除样本要有原因并保留记录。输出一个矩阵仅代表求解程序运行结束，不代表标定验收通过。

### 第六步 用独立姿态和深度数据验证

先用未参与求解的姿态重新观察固定板，检查计算出的板在基座下的位置和方向是否一致。再观察具有独立测量真值的工装目标点，检查绝对位置误差；否则多姿态一致仍可能存在共同偏差。

因为实际穴位使用深度反投影，必须另做深度链路验证：用当前深度对齐与反投影流程得到固定目标的camera_point_mm，经过手眼变换转到基座，和工装真值比较。RGB棋盘格PnP标定很好，也不能自动证明深度采样、RGB-D对齐和机器人坐标全链路正确。

验证覆盖实际工作区、观察距离和不同高度，记录平均误差、最大误差和重复测量离散程度。允许误差应在测试前按工具和目标精度确定，本文件不虚构一个人体服务安全阈值。未达到范围则检查板尺寸、位姿解释、时间配对、支架刚性、内参和深度质量后重新采集。

### 第七步 保存结果并接入三进程系统

预期保存：相机内参与流配置、相机到安装参考的4×4变换、参考连杆名称、工具TCP配置、原始数据和验证报告。可以采用camera_intrinsics.json、hand_eye.yaml等文件名，但在实际标定之前不要创建单位矩阵冒充真实标定。

运行时保持原有分工：视觉进程提供穴位相机坐标与采集信息；控制进程读取/配对实际参考位姿，计算基座坐标，再做路径和工具位姿处理；UI只显示定位是否有效及工作状态。

```text
p_base = T_base_flange(t_capture) × T_flange_camera × p_camera
```

相机或支架重新安装后重新标定/验证。更换TCP时更新工具配置；相机固定关系没变不必无条件重求手眼，但必须确认换工具未影响相机安装和碰撞外形。人体/床姿态变化则重新定位或更新床变换。

## 5 当前最先准备的四件事

1. 确认实际支架固定在法兰输出侧还是腕部外壳，并完成不会松动的安装件。
2. 准备一块尺寸已知、平整哑光的标定板及固定底板/夹具。
3. 确认可读取真实的基座下法兰位姿，或能从已知TCP配置正确换算。
4. 增加“停稳后保存图像和机器人位姿”的标定采集工具，再采样求解和验证。

现有zhenjiu程序提供采集和深度反投影基础；不能仅用已有穴位快照代替完整手眼标定数据。手眼标定验证通过后，还需分别验证表面方向估计与穴位识别精度。
