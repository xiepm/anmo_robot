# 希康智能初版通讯与主功能验收标准

版本：V0.1 · 2026年10月8日 · 本文件为待执行验收清单，不是测试通过报告。

配套：[通讯与状态机](希康智能_上下位机通讯协议与状态机_V0.1.md)、[全部报文示例](希康智能_初版完整报文示例.md)。只验收已约定的5个命令和6个主状态，不增加暂停、归档或权限功能。

## 1 如何验收

先在同机模拟器中检查报文、状态机、计时和异常处理，再在关闭能量输出的工装环境中检查真实机械臂运动和停止。真实视觉、温控或力控模块接入后，再分别验收其能力。模拟器通过只能证明软件流程，不代表实机或人体服务可以投入使用。

每条用例按“准备前置状态 → 执行步骤 → 保存消息与执行日志 → 对照通过条件”执行。日志记录本机单调时间、消息方向、完整报文、状态变化、设备调用及反馈；时间记录在测试日志里，不给业务报文增加ID。每条结果填写通过、失败或未验收，未接入模块只能标记未验收。

工装中的三种部位是三组测试配置，不要求模拟器具有真实人体几何。上肢/下肢报文所用名称已在本地穴位代码中出现，但名称存在不等于识别准确。实机测试须采用本次已经确认的点位、工具和退出路径。

## 2 软件联调通过门槛

以下数值是初版模拟/同机软件验收目标，不能解释为已实现性能或设备安全等级。实际设备停止、控制闭环及保护阈值另按第5节确认。

| 项目 | 检查方法 | 初版通过条件 |
|---|---|---|
| UI巡查请求 | 正常运行60秒，记录相邻GET_STATUS到达时间 | 配置周期1秒；相邻间隔0.8至1.2秒，无漏发造成的误停止 |
| 下位机定期上报 | 正常运行60秒，区分定时推送和额外即时推送 | 定时周期200ms；定时消息间隔150至300ms，不出现超过500ms的状态空档 |
| 模拟设备采集 | 查看采集任务日志 | 周期100ms；采集间隔不超过200ms；真实SDK采集能力另测 |
| GET_STATUS返回 | 发送请求后计时，使用服务端日志区分定时推送 | 接收完整请求后200ms内发送完整STATUS |
| 普通请求回复 | 从完整请求到REPLY | GET_STATUS除外，目标500ms内；复杂扫描结果不用在该时限内完成 |
| 状态变化上报 | 从下位机状态提交到STATUS发出 | 200ms内，不等下一个耗时动作结束 |
| UI显示状态过期 | 丢弃下位机输出但保持UI定时器运行 | 距最后有效STATUS超过1秒后，在下一次200ms巡查内显示过期，即最迟1.2秒 |
| UI存活超时 | 保持连接打开但停止所有UI请求 | 从最后合法请求算起，3秒至3.2秒内触发停止处理 |
| WebSocket明确关闭 | 关闭连接并记录下位机收到关闭通知时间 | 收到关闭通知后200ms内触发停止处理，不另等3秒 |
| 软件STOP响应 | 模拟器中在任一阶段发送STOP | 收到请求后200ms内置停止标志、禁止新段并启动停止处理；500ms内回复受理 |
| 模拟停止确认 | 模拟器设置正常停止反馈延迟100ms | 收到STOP后500ms内到IDLE；不得早于模拟停止反馈 |
| 模拟停止确认失败 | 将模拟停止阶段超时配置为2秒，屏蔽停止反馈 | 2秒至2.2秒内进ERROR；不得到IDLE/COMPLETED |
| 模拟反馈失效 | 新鲜度阈值配置500ms，冻结机器人或必要传感器反馈 | 最迟700ms将其标为无效并触发故障处理；持续STATUS不能掩盖采集冻结 |
| 分穴计时 | 总60秒，3点；测量每次DWELL且有效的累计时间 | 每点20秒，误差不超过200ms；总有效时间60秒，误差不超过600ms；过渡时间不计入 |
| 重复开始 | 连续快速点击或注入10次START | 只产生一次任务启动，其他请求拒绝；完成后迟到START也不再启动 |

所有持续时间使用单调时钟。消息接收延迟与UI绘制延迟分别记录，不用屏幕肉眼倒计时代替测量。真实机器响应不满足软件目标时应记录实测值并评审调整，不能修改记录掩盖失败。

## 3 功能验收用例

### 通讯与上位机行为

| 用例 | 前置条件与操作步骤 | 预期结果与通过条件 |
|---|---|---|
| A01 同机连接 | UI和控制进程部署在同机，连接127.0.0.1:8765 | 成功交换JSON；不需要第二台电脑；初版仅允许一个UI控制连接 |
| A02 无编号协议 | 逐一读取完整报文场景，并发送合法请求 | 无请求/方案/穴位ID；请求仅cmd和data，目标用部位、名称、侧别；所有合法示例可解析（非法格式用例按预期拒绝） |
| A03 查询正常与故障 | 分别在IDLE、READY、RUNNING、STOPPING、SCANNING、ERROR发送GET_STATUS | 合法请求始终返回完整STATUS，不额外发REPLY；故障状态可读，遵守200ms响应目标 |
| A04 定期巡查与上报 | 无用户操作，运行60秒 | UI仍每秒查询，下位机仍每200ms推送；符合第2节时限 |
| A05 即时状态上报 | 依次触发开始、停止、完成及模拟故障 | 状态变化200ms内上报，UI显示对应状态；不能仅依赖本地按钮改变显示 |
| A06 无数据与目标值 | 未配置传感器，然后配置目标但不提供反馈 | 实际值为null、valid=false；UI显示无数据，不把47或15的目标值显示成实测值 |
| A07 状态过期 | 保留连接，丢弃所有下位机到UI的消息 | UI最迟1.2秒提示过期，禁用开始/扫描/确认；可发送STOP但不得自行显示已停 |
| A08 格式错误 | 发送未知cmd、缺字段、错误data类型、多余字段、非法JSON | 返回失败REPLY；cmd可识别则回显，否则null；无运动、无进程崩溃，不改变现有任务 |
| A09 无ID时顺序处理 | 普通请求等待回复时尝试再发普通命令，再点击STOP | UI不并发普通控制请求；GET_STATUS不受阻；STOP可优先处理，旧回复不解锁过时操作 |

### 定位与参数

| 用例 | 前置条件与操作步骤 | 预期结果与通过条件 |
|---|---|---|
| B01 三部位通用 | 分别配置BACK、UPPER_LIMB、LOWER_LIMB，执行SCAN | 三者使用同样字段和命令；SCANNING→IDLE，positioning_valid=true，返回对应点列表；不自动工作 |
| B02 扫描失败/未接视觉 | 分别注入无深度和模块未接入 | 已受理扫描失败回IDLE并清空定位；未接模块直接拒绝；两者均不得伪报定位成功 |
| B03 取消扫描 | SCANNING时STOP，再注入迟到扫描成功回调 | 停止后定位仍无效，旧回调不得恢复可用点或进入READY |
| B04 切换部位 | 完成背部定位/方案后，改为上肢；不扫描先提交上肢方案 | 方案被拒绝；扫描上肢后旧背部定位与方案作废，再次确认后才可开始 |
| B05 左右与中线 | 使用背部左右肩井和中线点，屏幕切换或镜像显示 | LEFT/RIGHT始终按人体自身方向；错误侧别拒绝；UI和下位机选中的是同一点 |
| B06 六种方案结构 | 三个部位分别提交温度和力方案，模拟器开启对应能力 | 完整参数回显；READY；力方案无gap_mm；温度方案有gap_mm；无需新增命令 |
| B07 参数非法 | 逐项测试空点、未知点、重复名称侧别、负数/零/非整数时间、不能均分、错单位、超范围、缺间隙、未支持手法和过渡 | 每项均拒绝且说明原因；在IDLE/READY提交失败会清除旧待执行方案，不能继续START |
| B08 当前定位/能力缺失 | 无定位、定位部位不匹配或末端能力关闭时提交方案 | 拒绝，不降级成未经声明的实机执行；无运动、无输出 |
| B09 运行中修改 | RUNNING时SET_PLAN或SCAN | 失败回复；不清除、替换或排队覆盖当前运行方案 |
| B10 UI未提交修改 | READY后仅修改UI草稿，不点击确认 | START按钮禁用；确认成功后回显参数与UI一致才可开启 |

### 执行 停止与计时

| 用例 | 前置条件与操作步骤 | 预期结果与通过条件 |
|---|---|---|
| C01 三点完整执行 | 背部3点60秒，START后观察全部阶段 | 接近→停留→抬离→过渡，按列表顺序执行；最后退出确认后IDLE/COMPLETED；符合计时门槛 |
| C02 上下肢复用执行 | 对上肢、下肢分别提交2点60秒并START | 每点30秒，使用同一状态机；路径使用对应部位当前定位，不沿用背部坐标 |
| C03 无方案和重复开始 | IDLE发START；READY连续发10次START；完成后再发迟到START | 无方案时拒绝；连续启动只执行一次；完成后清方案，迟到START仍拒绝 |
| C04 SDK已受理但未到位 | 模拟SDK立即返回成功，延迟实际到位反馈 | 保持APPROACH，停留计时不开始；收到发送后的当前动作到位反馈才进DWELL |
| C05 过渡不扣时间 | 将接近/抬离/跨点各延长若干秒 | 有效工作总时长仍60秒；运行墙钟时长相应增加；不能提前宣布完成 |
| C06 各阶段停止 | 分别在APPROACH、DWELL、RETRACT、TRANSFER时STOP | 均满足软件STOP时限，未执行点不再执行；实际停止确认后IDLE/STOPPED，不自动回安全位 |
| C07 其他状态停止 | 分别在IDLE、READY、SCANNING、STOPPING、ERROR发STOP | 按协议处理；READY清方案，SCANNING取消；重复STOP不重置超时；ERROR不清故障 |
| C08 停止失败 | 模拟停止无反馈，等待2秒阶段超时 | ERROR/FAILED，保留未知停止说明；不能显示已停或已退让 |
| C09 停止打断待完成任务 | 在计划校验/扫描/动作尚未返回时STOP，然后送迟到成功回调 | 后续不得进入READY/RUNNING或新增运动；已停止状态不被旧成功覆盖 |
| C10 反馈失效时计时 | DWELL中冻结温度或力反馈 | 达到有效期门槛后进入ERROR，冻结有效时间并停止处理；不一边报无数据一边继续工作 |

### 断联 故障与重启

| 用例 | 前置条件与操作步骤 | 预期结果与通过条件 |
|---|---|---|
| D01 UI存活超时 | 保持连接但停止GET_STATUS及其他请求 | 3至3.2秒内进入停止处理；连接仍可发消息时上报原因；不等UI确认 |
| D02 UI关闭与重连 | RUNNING时关闭UI，停止确认后重开UI | 连接关闭后200ms内启动停止处理；重连先查状态；不自动重发方案/START |
| D03 控制进程退出 | RUNNING模拟中终止控制进程，再启动 | UI显示连接异常；后端重启不重放旧动作，无可信设备反馈时ERROR；初始化通过后IDLE且方案清空 |
| D04 设备反馈冻结 | STATUS发送线程正常，停止SDK新鲜反馈 | robot_feedback_valid=false；ERROR；UI不能因STATUS持续到达而显示设备正常 |
| D05 设备断联/急停 | 模拟运动期间断联或急停有效 | ERROR，取消后续动作；不自动退让或复位；STOP/重连不清故障、不自动继续 |
| D06 新人体/工具 | READY后模拟人体移动或工具变更，随后START | 拒绝开始，清除定位/方案，要求重新定位确认；不能使用旧坐标 |

## 4 测试证据与记录格式

每条用例至少保存下列信息，出现失败要保留原始消息和实际结果，不能只截图“通过”。表内编号是测试条目名称，不进入通讯报文。

| 用例 | 环境及前置条件 | 实际步骤/输入 | 实测响应时间 | 实际状态与消息 | 结论 | 日志或截图路径 |
|---|---|---|---|---|---|---|
| A01等 | SIMULATION或工装实机；软件版本和配置 | 具体操作 | 毫秒；不适用则说明 | 与预期比较 | 待执行/通过/失败/未验收 | 本机证据路径 |

异常注入在模拟器或受控工装环境执行。UI掉线、控制进程退出、机器人断联分别测试，不能拿一种断联测试代替三种。重启后是否运动必须用设备调用日志和真实反馈核对，不能只看UI。

## 5 实机能力的单独验收

| 项目 | 开始前必须确定 | 通过条件 |
|---|---|---|
| 真实机械臂运动 | 已确认的测试点、姿态、路径、工具配置，允许位置误差和速度范围 | 各点实测位置/姿态及路径符合约定，阶段反馈匹配当前动作；不能仅凭SDK返回0通过 |
| 实际停止 | 固定测试速度/负载、厂家支持的停止方式、停止时间及距离允许上限 | 测量软件请求至机械臂实际停止的时间/距离，均在事先确认范围；未确定范围则该项未验收 |
| 真实视觉 | 各部位点位真值、允许定位误差、允许失败率和失效识别条件 | 在约定样本中符合预先确定阈值；人体移动后旧定位失效；只返回名称不算定位通过 |
| 真实温控 | 测温对象、传感器及执行器、允许偏差、上下限、响应时间 | 实测与目标对应、偏差/响应符合约定，传感器失效和超限触发处置；不能用模拟值替代 |
| 真实力控 | 力方向、传感器标定、工具、允许误差和最大力 | 实际接触力及偏差符合约定；失效/超限触发处置；仅存在SDK函数不算能力通过 |
| 工控机/电箱故障保护 | 现场硬件急停及独立保护配置 | 在授权工装测试中按硬件设计执行；不能仅依赖UI和控制进程相互检测 |

本任务只提供协议与验收文件，没有批准或执行上述实机测试。不能在未确认设备能力及允许范围时，将本文软件测试阈值用作人体服务阈值。

## 6 初版验收结论怎么判

同机模拟通讯与主流程验收通过，需要第3节全部适用用例通过且有证据。未接入的视觉/真实末端可列为未验收，但结论必须写明“模拟通讯与流程通过”，不能写成“整机通过”。工装运动通过也不自动等于真实能量控制通过。

存在重复启动、停止不能打断、已停止任务被迟到回调恢复、无效反馈被显示为正常、断联后自动继续等任一问题时，初版主流程验收不通过。

本次交付仅完成报文文件的静态检查；以上用例均待运行系统实施测试并填写结果。


## 7 随动相机方案补充验收

2026年10月10日补充。相机改为机械臂末端法兰侧安装后，增加以下5项；前述35项基本协议用例保持不变。以下均待执行，观察位先由现场调试准备，SCAN本身不驱动机器人移动。

| 用例 | 操作步骤 | 通过条件 |
|---|---|---|
| E01 观察位与视野 | 分别在背部、上肢、下肢观察位停稳采集 | 本次所需人体关键点及深度有效，工具未遮挡；观察和接近路径包含相机支架/线缆外形检查 |
| E02 移动中拒绝扫描 | 机器人尚在移动、未停稳或不满足观察条件时SCAN | 拒绝采集请求，不自动移动到观察位，不使用旧图像宣布定位成功 |
| E03 多姿态变换一致性 | 相机从多个未参与标定的姿态观察同一固定工装点 | 基座下坐标彼此一致且与独立测量真值偏差均小于事前确定阈值；没有阈值或测量证据则未验收 |
| E04 图像与法兰位姿配对 | 注入旧图像或旧位姿，随后测试停稳后新鲜配对 | 旧数据配对被拒绝；按实际采集姿态转换；机器人之后移动不造成已保存静止点的基座坐标变化 |
| E05 安装或工具变化 | 改变相机安装关系或工具TCP配置后尝试沿用原结果 | 原定位/方案不得直接使用；相机关系变化重新标定，工具变化更新TCP/负载/碰撞参数后重新验证 |

静止采集成功只证明本次数据配对，不代表已经具备运动中的在线视觉控制或持续人体运动跟踪能力。
