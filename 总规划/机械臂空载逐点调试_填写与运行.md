# elfin5_l 空载逐点调试：填写与运行

2026-10-12 更新。**已完成首轮真实运动验收**：返回起点，然后 P1 → 自动中间点 → P2 → P3，各原始点停留 2 秒，最后确认停止。当前已恢复只读反馈与模型显示。详细数据见[实机记录](../src/massage_controller/reports/waypoint_runs/实机逐点调试记录_20261012.md)。

执行输入：[waypoints.json](../config/commissioning/waypoints.json)。展开路径预览：[waypoints.preview.json](../config/commissioning/waypoints.preview.json)。预览是审阅文件，实际执行只读取输入文件，运行日志记录本次真正展开的路径。

## 1. 坐标与实体工具

本轮用户明确：点位是在示教器 TCP=0 时记录的**法兰相对 Base 的位姿**；实体物件沿法兰自身 +Z 突出 20 mm。因此当前配置如下：

```json
"target_reference": "FLANGE",
"tool_pose_mm_deg": [0, 0, 20, 0, 0, 0]
```

- `FLANGE`：XYZ/RxRyRz 表示法兰目标。运动命令用零 TCP，实际反馈也要求控制器当前 TCP 为零。`tool_pose_mm_deg` 在此模式记录实体工具几何，不把这些法兰点误当成物件尖端目标，不修改控制器全局 TCP。
- `TCP`：XYZ/RxRyRz 表示工具尖端目标。命令使用 `tool_pose_mm_deg`，反馈要求当前控制器 TCP 与之匹配。这是与 FLANGE 不同的物理目标定义，不能只改标志后沿用同一组坐标。
- 所有目标相对机器人 `Base`，控制器当前 UCS 必须是零变换。XYZ 单位 mm，Rx/Ry/Rz 单位 °，沿用华沿示教器/SDK 定义，不直接套用 ROS RPY。
- 20 mm 是工具局部坐标偏移，不是基坐标 Z 增加 20 mm。工具随法兰转动，其尖端在基坐标系中的偏移方向也改变。
- 本程序不配置负载、不自动使能或复位，不包含工具/连杆碰撞检测、温控、力控或人体接触功能。工具负载及现场路径需与实际安装相符。

## 2. 起点和返回路径

`start_pose` 是正式执行 P1 前要求到达的位置。

- 不填写 `return_from_pose`：机械臂必须已在 `start_pose` 停稳，才允许 START。
- 填写 `return_from_pose`：表示已经确认从这个位置到 `start_pose` 的直线路径。机械臂必须位于该位置或起点附近；不会从任意位置自动回起点。
- 在允许的返回位置启动时，显示 READY 后输入 START，先执行 `RETURN_TO_START`，到位停稳后才执行 P1。
- READY 等待期间位置发生变化会拒绝执行，要求重新核对。

本次结束后 `return_from_pose` 已更新为实际完成并验证过的 P3 目标位置，便于下次从 P3 返回起点。若使用示教器移动到其他位置，应重新确认返回路径并填写其起始位置，或手动回到 start_pose。

起点/目标到位容差：位置欧氏距离 1 mm、厂家姿态各分量 0.5°。这些是程序阈值，不是机械臂精度指标。当前 TCP/UCS 匹配容差为 0.01 mm / 0.01°。

## 3. 逐点填写

JSON 的 `points` 是原始目标点，可按顺序增删；原始点到位停稳后执行各自 `dwell_s`。不自动返回起点，不循环重跑；最后停在最后一个点。

| 位置 | X / mm | Y / mm | Z / mm | Rx / ° | Ry / ° | Rz / ° | 停留 / s |
|---|---:|---:|---:|---:|---:|---:|---:|
| start_pose | -668.772 | 55.791 | 154.666 | 179.508 | -2.382 | -175.413 | — |
| P1 | -490 | 338 | 91 | 179 | -2 | -175 | 2 |
| P2 | -704 | -273 | 91 | 179 | -2 | -175 | 2 |
| P3 | -487 | -155 | 104 | 179 | -2 | -175 | 2 |

上表是本次测试记录。**后续修改以 JSON 为准，程序不读取本文表格。** 要抬离或绕行，应把抬离点和转移点明确加入数组，不能把“直线插点”当成自动避障。

## 4. 自动插点与连续过渡

当前开启 `auto_subdivide: true`。对于固定姿态的长直线，按 `max_segment_mm` 等分，保留原几何直线；例如 P1→P2 约 647.392 mm，会在 400 mm 上限下生成中点：

```text
[-597, 32.5, 91, 179, -2, -175]
```

生成的两段各约 323.696 mm。插点无额外停留，使用最大 5 mm、且不超过相邻段长度四分之一的 SDK 过渡半径；原始目标点半径始终为 0，需停稳并执行原停留时间。程序只预先下发当前原始直线段的子路点，不提前下发后续原始目标点。

本次实测中间点附近持续 `moving=1`，没有中途停车。自动插点只改善分段执行，不缩短总行程，不保证避障，也不代表全程恒速。实际控制器会按自身运动限制处理过渡。

超长段同时改变姿态时，当前版本拒绝自动猜测姿态插值，需提供已确认的中间位姿；不能未经核对直接对厂家欧拉角插值。原始短段姿态变化仍按 `max_rotation_deg` 检查。

## 5. 参数说明

| 字段 | 当前含义和范围 |
|---|---|
| `version / mode / robot_model / frame` | 保持 `1 / FREE_SPACE_WAYPOINTS / elfin5_l / Base` |
| `path_confirmed` | 确认返回起点、起点到首点、点间完整路径后设为 true |
| `target_reference` | `FLANGE` 或 `TCP`；缺省 TCP，见坐标解释 |
| `tool_pose_mm_deg` | 实体工具相对法兰的六维变换；FLANGE 模式不把它作为命令 TCP |
| `return_from_pose` | 可选，已确认返回起点路径的起始位姿 |
| `start_pose` | 执行原始目标点之前的起点 |
| `auto_subdivide` | 自动拆分固定姿态长直线；缺省 false |
| `speed` | SDK 速度参数；平移 mm/s、旋转 °/s；允许 0.1–20，本次 20 |
| `acceleration` | SDK 加速度参数；平移 mm/s²、旋转 °/s²；允许至 40，须大于 speed，本次 40 |
| `max_segment_mm` | 每个下发子段最大位移，0.1–500 mm，本次 400 |
| `max_rotation_deg` | 单段姿态各分量变化上限，0.1–30°，本次 10 |
| `workspace_mm.min / max` | 当前参考点（法兰或 TCP）的 XYZ 范围，不包含工具/连杆碰撞检查 |
| `move_timeout_s` | 原始移动段的到位超时，1–300 秒，本次 60；自动插点不重置整段超时预算 |
| `points[].name / pose / dwell_s` | 唯一点名、六维目标、0–60 秒停留 |

静态检查会拒绝距离除以速度已经超过超时的方案；通过仍不保证实机能在预算内到位。加减速、控制器倍率等也影响耗时。软件速度和范围上限不是厂家认证的安全限值。

## 6. 运行

先校验，不连接设备、不发送命令：

```bash
cd /home/xpm/rehabilitation
scripts/waypoint_test.sh config/commissioning/waypoints.json
```

在现场交互终端执行前，先退出已有只读/控制进程。当前由统一启动器管理，可用：

```bash
python3 scripts/stop_real_debug.py
scripts/waypoint_test.sh config/commissioning/waypoints.json --execute
```

也可直接使用控制主进程入口：

```bash
scripts/start_control.sh --waypoint-plan config/commissioning/waypoints.json --execute
```

`--execute` 连接、检查真实状态，并在已停稳条件下先发一次普通 GrpStop，验证响应和停止反馈。它不自动移动。READY 后在终端输入 `START` 并回车，才开始返回起点/逐点执行。提前 START 会被拒绝；运行期间改文件不会修改本次冻结方案。

输入 `STOP` 并回车或 Ctrl+C 请求实际普通停止，也支持：

```bash
scripts/controller_runtime.sh ros2 topic pub --once /control_node/stop std_msgs/msg/String '{data: "STOP"}'
```

普通软件停止不是硬件急停。停止未确认会显示 `STOP_UNCONFIRMED`，应现场使用示教器/硬件停止。不要通过强制杀死进程代替停止。

## 7. 到位与异常处理

执行器先在真实反馈中观察本次唯一的路点 ID，再检查实际位姿与连续三帧停稳。已验证本控制器会在运动完成后把路点 ID 清空，因此到位后允许空 ID；只看到空 ID 或机械臂原本静止都不能视为运动完成。

停留期间要求位置保持、反馈有效、机械臂停稳。SDK 工作线程约 100 ms 读取，单次网络交换超时 150 ms，反馈超过 500 ms 判无效。主线程处理终端和 ROS，不被 SDK 读写阻塞。

故障、超时、过期、停止请求或日志错误会中断方案并尝试停止；响应不确定不重发运动，不会断线重连后续跑。必要重连只用于尽力停止。最终只有真实停止反馈确认成功才显示 COMPLETED/STOPPED。

## 8. 可视化及代码

执行期间另开终端运行 `scripts/start_robot_mirror.sh`，可显示跟随真实角度的模型。不要再开另一个 SDK 读取或控制进程。本项目客户端有设备锁，但不能管理厂家示教器或第三方控制软件。

真实数据：`/robot/joint_states`、`/control_node/robot_telemetry`；本调试状态：`/control_node/status` 的 `WAYPOINT_STATUS`。物件几何记录不代表 RViz 已加入对应碰撞模型。

本模式独占业务端口 8765/8766，但不提供 UI/视觉 WebSocket 业务服务。正式 SET_PLAN 仍是穴位、顺序和工作参数，默认 REAL 业务路径仍只读；没有伪造视觉定位、温度或力反馈。

代码位于 `src/massage_controller/massage_controller/waypoint_plan.py`、`waypoint_motion.py` 和 `waypoint_runtime.py`。日志为 `src/massage_controller/reports/waypoint_runs/*.jsonl`，记录完整方案、展开路径、真实反馈、状态及 SDK 命令审计。
