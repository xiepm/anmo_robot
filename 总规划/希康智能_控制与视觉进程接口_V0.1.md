# 希康智能控制与视觉进程接口

版本：V0.1 · 2026年10月10日 · 三进程分工开发的接口基线，尚未实现。

## 1 连接与边界

control_node与vision_worker使用本机WebSocket JSON，建议地址为ws://127.0.0.1:8766/vision。control_node是服务端，vision_worker是客户端；只允许一个视觉连接。UI继续使用8765端口，两条通道分开，均由control_node进程管理，不新增网关进程。

视觉进程独占D435i，运行现有Python环境，负责图像采集、穴位计算和相机坐标输出。控制进程负责法兰位姿、手眼变换、基座坐标、业务状态机和机器人运动。视觉进程不打开机械臂SDK，不请求运动；UI不直接访问视觉进程。

初版继续使用无请求ID、无穴位ID的消息。每次只允许一个定位任务。下列命令是内部接口，不加入UI的5个命令。

## 2 定位命令

control_node在收到UI的SCAN且确认机械臂已经在观察位停稳后，发送LOCATE。region、view分别表示任务部位和明确配置的拍摄面；不能仅从BACK/UPPER_LIMB/LOWER_LIMB自动猜测人体正反面。初版view取front或back，由控制配置提供。

```json
{
  "cmd": "LOCATE",
  "data": {"region": "BACK", "view": "back"}
}
```

视觉端接收后立即回复，随后异步采集，不能把模型推理放在通讯回调里：

```json
{
  "type": "REPLY",
  "cmd": "LOCATE",
  "ok": true,
  "message": "定位请求已受理",
  "data": {}
}
```

失败回复格式相同，ok=false并说明原因；拒绝LOCATE不再产生本次LOCATE_RESULT。正在定位时第二条LOCATE应拒绝，不排队。控制端在LOCATE结果不明时不能自动重发。

## 3 定位结果

完成后发送LOCATE_RESULT。每个已受理任务仅产生一个逻辑终态，status为SUCCEEDED、FAILED或CANCELED。下面是数据格式示例，数值是模拟值；capture时刻不能照抄用于运行。

```json
{
  "type": "LOCATE_RESULT",
  "data": {
    "status": "SUCCEEDED",
    "region": "BACK",
    "view": "back",
    "capture_host_monotonic_ms": 123456789,
    "capture_time_valid": true,
    "frame": "camera_color_optical_frame",
    "points": [
      {
        "name": "大椎",
        "side": "MIDLINE",
        "camera_point_mm": [10.0, -20.0, 800.0],
        "coordinate_valid": true,
        "normal_camera": null,
        "normal_valid": false
      }
    ],
    "message": "定位完成；本次尚无有效表面法向"
  }
}
```

| 字段 | 约定 |
|---|---|
| region | 与任务一致；BACK、UPPER_LIMB、LOWER_LIMB |
| view | front或back，返回实际使用的配置 |
| capture_host_monotonic_ms | 采集时刻映射到宿主单调时钟的毫秒值，不能用推理完成时间冒充 |
| capture_time_valid | 是否已得到可信的宿主采集时间；无效时capture时间为null |
| frame | 固定为camera_color_optical_frame，指当前彩色光学坐标系 |
| name / side | 项目统一名称；LEFT、RIGHT、MIDLINE；视觉代码原有L/R等需在适配层转换 |
| camera_point_mm | 相机坐标XYZ毫米值，3个有限数；无效时为null |
| coordinate_valid | 有效深度三维坐标标志；不代表解剖定位精度已通过 |
| normal_camera / normal_valid | 指向体外的单位表面法向及有效性；尚未实现时null/false，不填虚构方向 |

双方使用同机CLOCK_MONOTONIC毫秒基准，并验证容器/进程没有不同时间命名空间。相机设备时钟需要映射；单纯在收到帧时调用time.monotonic不等于曝光时间。初版保持停稳，控制端必须证明采集发生在本次静止窗口内：排除旧缓冲帧，并核对采集前后位姿。不能证明时拒绝将该结果用于真实运动。

成功至少包含一个coordinate_valid=true的点，且不存在同名同侧重复点；无有效点按FAILED处理。只有control_node能判定定位是否足够用于方案和运动。上例即使SUCCEEDED，仍不具备真实执行所需法向；控制端应报告缺项并拒绝真实方案。模拟/工装测试可以用单独明确配置的工装几何，不能伪装成人体实测法向。

失败完整示例：

```json
{
  "type": "LOCATE_RESULT",
  "data": {
    "status": "FAILED",
    "region": "BACK",
    "view": "back",
    "capture_host_monotonic_ms": null,
    "capture_time_valid": false,
    "frame": "camera_color_optical_frame",
    "points": [],
    "message": "未获得有效人体深度坐标"
  }
}
```

## 4 取消与迟到结果

```json
{"cmd": "CANCEL", "data": {}}
```

```json
{"type": "REPLY", "cmd": "CANCEL", "ok": true, "message": "取消请求已受理", "data": {}}
```

如果存在未完成任务，视觉进程使其结果失效，并发出该任务的LOCATE_RESULT，status=CANCELED，points为空，采集时间null/false，其余字段与该任务一致。无活动任务时只回复“当前没有定位任务”，不额外发终态。

控制端发出CANCEL时立即使当前结果不可用于业务，不等待视觉才能停止机械臂。视觉无需强行终止底层推理调用，但必须丢弃取消后完成的结果。新LOCATE必须等待旧任务终态及取消处理完成；到期无响应则关闭本次视觉连接，待旧处理取消/退出并重新连接后再启动新任务。终态和取消并发时，只承认一次逻辑终态，控制端不得利用已取消的成功结果。

连接断开后控制端清除待定位任务和当前定位有效性；视觉端丢弃旧连接任务及待发送结果。新连接不重放旧结果。允许内部使用局部取消标志/代次变量，但不增加消息ID字段。

## 5 视觉健康状态

视觉进程连接建立后及每1秒发送VISION_STATUS，状态变化立即发送：

```json
{
  "type": "VISION_STATUS",
  "data": {
    "mode": "SIMULATION",
    "camera_connected": true,
    "model_ready": true,
    "worker_state": "IDLE",
    "last_frame_age_ms": 40,
    "error": ""
  }
}
```

worker_state为IDLE、LOCATING或ERROR。mode为REAL或SIMULATION，控制进程必须检查模式相符。last_frame_age_ms是最近成功接收帧距发送健康状态的宿主单调时间差，无帧为null；它只反映采集活性，不代替定位图像的曝光时刻。

控制端连续3秒未收到合法健康状态时判视觉不可用；LOCATE默认30秒超时，可配置。没有相机、没有模型、模式不匹配、图像过期或视觉错误均不能通过真实SCAN。视觉失联不自动把控制进程已完成的正常会话改为运行，也不在重连后自动继续服务。

## 6 开发交付与验收

控制任务实现8766服务端及视觉模拟器客户端；视觉任务实现正式客户端和本地控制端桩，模拟器只用于测试，不计入正式3个业务进程。双方先用同一套消息验证以下情况，再连接真实模型：

1. 合法LOCATE受理并返回单次终态；非法/重复LOCATE拒绝。
2. 失败、无深度、无采集时间和无法向均不伪造有效数据。
3. CANCEL后迟到推理结果不会启动或恢复旧业务；完成/取消并发不重复终态。
4. 断连、心跳超时、30秒定位超时均可检测，不自动重放任务。
5. 名称/侧别、毫米单位、坐标系和采集时刻正确传递。
6. 视觉端没有任何机器人运动调用；控制端在无真实标定时不产生真实运动。

此约定补齐三进程分开开发所需边界。真实采集时间映射、法向估计、手眼标定和实际定位精度仍是待实现/验证能力，不能用协议设计完成代替硬件验收。


## 2026-10-13 Base 预览兼容扩展

控制进程新增同端口 `/coordinates` 只读坐标转换接口；`PROJECT_POINTS` 和 `BASE_COORDINATES` 报文分别由 `config/rehab_protocol/base_coordinates_request.schema.json`、`base_coordinates_response.schema.json` 定义。视觉不持有 SDK。实机 `LOCATE_RESULT.data.base_preview` 为可选字段，保留原相机点协议；SIMULATION 不使用实机标定。

实际安装参考系经 J6 单轴实测为 `virtual_flange_with_joint6_zero`，不可直接使用实际输出法兰。Base 点在停稳接收时间窗口内计算，仅用于预览和后续控制联调，`capture_time_valid=false`、`motion_eligible=false`；既有定位/运动门禁不由此解锁。完整启动、变换、有效期和后续验收要求见 `zhenjiu/README_base_coordinates.md`。
